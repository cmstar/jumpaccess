# 版本发布说明

本目录保存维护者或 Agent 整理的逐版本发布说明正文。完整的版本规则、比较基准、预览命令及发布步骤见[版本发布规范](../standards/release.md)，构建与权限见[自动发布](../development.md#自动发布)。

## 文件约定

- 使用完整标签命名：`<tag>.md`，例如 `v0.2.0.md`、`v0.2.0-beta.1.md`。正式版与所有合法非正式尾缀均使用同一机制，不限于 `pre`。
- 正文与本版代码一起提交，并确保目标标签指向的提交包含该文件。发布脚本默认读取目标提交中的文件，工作区未提交内容只在显式指定 `--notes-file` 的本机预览中使用。
- 缺少文件时，工作流给出警告并回退到 Conventional Commits 分类说明；文件存在但为空白时失败。新版本应主动准备完整正文，不依赖回退作为日常写作方式。
- 这里只保存正文源文件；Release API 清单和合成后的预览文件使用系统临时目录，不提交到本目录。

## 正文写法

默认使用中文，说明用户从比较基准升级后能获得什么。按实际内容选用“新功能”“改进”“问题修复”“兼容性与升级”“已知限制”等章节，省略空章节；不要求固定模板或为每个提交单列条目。

同一版本开发期间出现并修复的问题并入最终功能描述。已经影响比较基准版本用户的问题被修复时，才单列为修复；纯测试或内部调整只有产生明确的用户影响时才进入正文。核对真实代码差异和当前实现，不从提交标题推断未验证的能力。

正文不重复版本标题，也不包含统一的下载说明、校验值说明、签名提醒或完整变更链接；这些由脚本按标签和已发布比较基准追加。具体基准由共同脚本选择：正式版对比上一正式版，非正式版优先对比同一 `X.Y.Z` 的较低非正式版，没有时回到上一正式版。

例如，一项功能开发期间包含新增、补充测试和三次内部修正，正文可以合并为“支持通过 Agent 下载远程文件，并在完成后提供本地文件路径”；只有代码与验证确实支持该描述时才使用。不要把开发过程中的每次修正当作独立用户功能，也不要在发布说明里声称未执行的验证已通过。
