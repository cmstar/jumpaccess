## 背景与决定

原实现分别对远端捕获内容、远端暂存包、本地暂存包及还原内容计算 SHA-256。其中暂存包在远端准备后和本地解压前各被额外完整读取一次。用户优先考虑下载速度，接受保留 Python，选择移除这些内容哈希以减少 CPU 和文件扫描开销。

远端继续通过 Python 固定实际打开时的读取长度，拒绝短读，并生成不再修改的暂存包；只取得包大小，不扫描包内容。传输及本地还原核对准确长度，保留归档清单、路径与文件类型检查，并完整读取 gzip 以检查其尾部校验。原有 SFTP／SSH 与 ZMODEM 协议保护保持不变。

内部清单不再携带 SHA-256。MCP 返回类型保留已有可选 `sha256` 字段以减少 schema 变动，但新下载不填充该字段。不新增配置开关，不改变连接、超时取消和清理流程，不调整压缩格式或参数。认证、身份和请求去重等用途的哈希不属于文件内容哈希，仍保留。

## 代价与验证

大小一致不能证明内容逐字节一致。此方案不再提供额外的端到端 SHA-256 核验；原样传输文件发生等长内容替换时，不能依靠应用层长度检查发现。已有压缩文件仍保持原样，不为校验而解包。

回归应覆盖没有哈希的清单、传输包和还原长度不符、gzip 尾部损坏或截断、归档漏项与路径限制；继续验证持续追加、轮转、源文件截断、取消与清理。真实性能对比使用相同合成内容、相同传输协议和多轮测量，区分总耗时与准备／还原阶段，不以扫描次数减少直接推导提速比例。
