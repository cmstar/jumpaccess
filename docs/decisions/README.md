# 决策记录

## 用途

本目录保存重要决策的历史依据，说明当时的约束、取舍和原因。
重点记录项目偏离行业规范、团队规范或常见做法的情况，供后续开发者和 Agent 考据。
遵循惯例且没有特殊取舍的做法，无需单独记录。
当前技术选择和边界见[架构说明](../architecture.md)，开发约束见[开发说明](../development.md)。

## Agent 维护边界

- 已确定决策的原始正文保留当时的事实、约束、候选方案、取舍和结论，不随代码演进改写为最新实现，不删除后来失效的理由。
- “同步更新文档”指维护描述当前情况的基础文档、专项规范和方案；本目录仅更新顶部状态摘要、适用范围、关联链接和索引，并按时间追加后续说明。
- 普通实现调整未改变决策或适用范围时，无需更新记录；新的重要取舍另建记录。
- 阅读旧正文前核对状态、范围和后续说明。与代码不一致时，先核实迁移状态、当前规则和变更依据，不能通过重写历史正文迁就代码，也不能仅凭旧正文恢复旧实现。

## 新增与命名

- 在重要取舍确定或引入项目特例时新增记录，一份文档聚焦一个决策。单纯解除旧约束、回归既有规范时，可以只追加结束说明。
- 文件名使用 yyyyMMdd-title.md，不使用递增编号。同日的不同决策通过标题区分。
- 日期使用决策确定日期；补录时优先使用原日期，可依据 Git 提交等推定大致日期并注明依据及不确定性；仍无法推定时使用补录日期并说明。
- 补录历史只写已确认的事实和依据，未知原因明确标注，不根据当前实现编造理由。
- 草案可以正常修订，但须标明状态，不列入当前有效决策索引。

## 单条记录的结构

- 顶部状态摘要：决策日期、当前状态、仍有效与已失效范围、最近状态更新日期、后续依据和当前规则链接；涉及迁移时另列实施状态与迁移方案入口。
- 原始决策正文：当时的背景与约束、通常做法和偏离点、候选方案、最终决策及理由、影响和代价、重新评估或退出条件、相关依据；没有通行做法时说明关键取舍即可。
- 后续说明：按时间追加变化原因、证据补充或事实勘误，每条包含日期、涉及范围和依据，不覆盖原始正文或既有后续说明。

## 后续维护

- 新的重要取舍替代原决策时另建记录，新旧记录互相引用；旧正文保留，只更新状态摘要并追加变化说明。
- 部分被替代时明确具体条目及剩余有效范围，在相关章节添加指向后续记录的提示；仍有有效范围的记录保留在当前索引。
- 新决策确定但代码尚未迁移完成时，另标“迁移中”，当前架构和方案说明已切换与尚未切换的范围。不要将迁移进度误写成永久的部分替代，也不要提前将仍约束过渡期的记录移入历史索引。
- 迁移开始、范围发生实质变化或迁移完成时，更新状态摘要和索引并追加说明；具体步骤和进度维护在迁移方案中。
- 单纯回归既有规范且没有新的重要取舍时，追加结束日期、原因、范围或版本、恢复遵循的规范和变更依据即可，不强制另建记录，也不把旧正文改成常规做法说明。
- 全部特例结束后标为“已撤销（特例已结束）”；若只结束部分或仍在迁移，明确保留范围和过渡状态。整体不再适用后，才移入历史索引。
- 补充证据或更正事实时追加带日期和依据的说明，必要时在原条目添加提示；错别字、格式和链接可修正，但不能改变历史含义。
- 当前架构、业务规则、API、开发约定和有效方案同步更新到对应文档，使当前规则可直接查阅。
- 曾经生效的重要决策默认保留，不因失效而删除。历史记录较多时可按需移入 archive/，同步修正索引和引用并保留状态说明；重复、误建文件和无保留价值的草稿可清理。
- 两类索引均按下表的列名和顺序维护，新增记录时追加一行，文档使用相对链接；无记录时只保留表头和分隔行，转入历史索引时移动对应行并补齐结束信息。
