## 背景与取舍

使用者常下载持续写入的日志。JumpServer 的 SFTP 根可能限制在 home 或临时目录，不能将 SSH 的绝对路径直接交给 SFTP；交互终端里的 `sz` 又会占用当前通道。自动化下载需要减少传输量，并在应用中途退出或网络中断时如实说明远端状态。

可以让 Agent 自行执行压缩、下载和轮询，也可以全部使用终端 `sz`。前者将权限、路径映射和清理细节分散到各客户端，后者影响正在执行的命令。最终采用服务持有异步下载任务：复用现有传输实现，优先 SFTP，必要时使用专用 SSH 通道上的 ZMODEM；首版不增加手动协议配置。

## 决策与代价

每项任务使用独立连接，引用普通连接 ID 只取得固定的目标身份。连接、元数据和并发都有上限，因此下载不会占用普通命令执行位置，但仍消耗网关连接名额、CPU、磁盘和带宽。

远端以 POSIX/Python 3.7+ 临时程序实现有限读取与压缩；不是安装常驻代理。文件打开时固定本次读取长度并同步计算哈希，随后追加不纳入本次下载，协议回退使用同一份暂存内容。代价是需要该运行环境，且不提供跨文件或原地覆盖时的原子快照保证。

ZMODEM 的二进制输入不能复用普通命令的文本停止协议。下载监督进程将 SSH 输入 EOF 作为停止请求，并通过 stderr 独立确认受控进程结束；网关不送达 EOF 或确认缺失时返回未知，而不冒充取消成功。远端时限仍限制失联进程的运行时间。

远端只生成有识别前缀的归档文件，使用生成中后缀后发布，不创建任务目录或控制文件。只按本任务记录的精确路径与文件身份清理；不能确认进程结束时保留残留，不按前缀扫描删除其他实例的文件。异常退出后不恢复任务，是首版明确接受的限制。

## 重新评估条件

若目标普遍缺少 Python、网关不支持二进制 exec／EOF，或使用者需要跨重启恢复、上传及大于 4 GiB 的 ZMODEM 传输，应单独评估兼容方案；不能以占用现有人类终端或弱化结果确认作为无提示回退。

## 验证依据

本机模拟 SSH 网关连接 WSL，已验证 gzip／tar.gz 准备、目录还原、受限 SFTP 暂存映射、SFTP 中断回退真实 lrzsz，以及压缩期间 EOF 取消。有限读取测试覆盖追加、重命名轮转、截断和链接拒绝。以上不等同于所有 JumpServer 网关均已验收，生产网关与 macOS 原生环境仍需分别验证。

## 2026-10-21 真实网关验收补充

使用当前分支代码启动临时本地 HTTP MCP 服务，通过 `test207` 的真实 JumpServer 网关验收。源文件放在本次独占的 `/tmp` 测试目录，确认 SFTP 不能直接读取；服务识别 `${HOME}` 暂存映射后，单文件 gzip 经 SFTP 下载成功，目录 tar.gz 在真实 SFTP 读取 2048 字节后注入本地读取错误，自动回退服务器 `sz` 下载成功。两项任务均通过 `download_files` 受理与 `get_download` 等待到完成，本地还原内容 SHA-256 匹配，空目录恢复，远端探测文件、压缩包及 `.part`、测试源文件和本地下载临时文件均确认清理。

故障注入只用于触发回退，没有更改服务器权限或 SFTP 配置；ZMODEM 数据由目标服务器真实 `sz` 经专用 SSH 连接传回。目标 Python 为 3.12.3，本次验证正常结束确认，未覆盖真实网关的强制断网、取消或 Python 3.7 最低版本；上述本机取消测试范围不变。
