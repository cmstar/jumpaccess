# MCP 共享操作历史与文本日志

决策日期：2026-10-18。状态：有效，已实施于共享核心及 CLI／GUI。适用范围：MCP 操作、命令输入输出的内存保留、去重索引及日志投影；CLI 复用同一共享仓库。最近状态更新：2026-10-25，实施补充见文末后续说明。

当前规则：[MCP 设计](../specs/agent-mcp.md#重试与自动清理)、[架构说明](../architecture.md)。

## 背景与取舍

命令重试需要返回原执行及仍保留的结果。另建包含完整输入输出的日志库会重复持有大块数据，而单纯记录命令文字又无法支持结果查询。原实现的 10000 条已结束去重历史与 256 条执行历史各自有界，但不提供 GUI 和后续 CLI 通用的操作日志。

选择一个宿主级操作仓库，混合保留最多 3000 条记录，包括活动操作与服务、连接、查询事件。每次执行只拥有一份输入、结果和输出块；Map、日志事件及单任务／全局输出链表引用同一份数据。去重索引独立保留最多 2500 条元数据，包含活动项；两者差值不是固定保留名额。记录回收和索引回收可以独立发生，分别用结果过期和请求代号机制阻止重放。

仓库与 Engine 共享互斥锁，使跨实例总输出限额和混合回收保持一致。锁内不调用外部日志订阅者或 I/O。原始输入保留最多 16 MiB，输出单任务最多 8 MiB、宿主最多 64 MiB；上限限制载荷字节，不宣称限制整个进程内存。活动输入不能回收。重启后解除仓库到退休 Engine 的引用，避免保留旧索引和连接池。

GUI 采用终端式只读文本流，复用终端字体、字号、行高与 ANSI 色板。显示级别只作用于新接收的日志，既有文本不重写。显示／暂停缓存有独立行数和字符数上限；清空界面不改变业务历史。详细日志显示命令输入和执行状态，不显示 stdout/stderr 或环境变量。非零退出码、stderr 属于正常命令结果，传输失败和未知状态单独记录。

## 代价与重新评估条件

混合 FIFO 中高频查询或服务事件可以提前回收命令结果，客户端必须处理明确的过期和输出缺口。仓库共享锁降低锁顺序复杂度，但不能用于高耗时格式化或阻塞通知。后续若加入 ACK、持久审计或跨宿主日志查询，需要单独评估保留契约、隐私边界和容量策略，不能默认把当前内存日志当作永久审计记录。

## 2026-10-25 CLI 接入补充

CLI 已通过 `jumpctl mcp serve` 承载共享服务，前台日志复用同一 History、游标、回收与格式化规则，按级别分别写入 stdout／stderr。Ctrl+C 停止服务后保留终端已输出的文本与滚动历史，进程内业务历史仍按原规则随宿主退出而丢失。本次接入不新增日志仓库、不改变结果和去重保留契约，也不改变原决策。CLI 验证范围为本机自动化与集成测试，macOS 原生及真实 Agent 客户端仍需验收；当前规则见 [CLI 前台日志与输出](../specs/agent-mcp.md#cli-前台日志与输出)。
