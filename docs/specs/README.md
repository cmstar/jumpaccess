# 需求与设计

## 用途

本目录存放具体需求、功能、重构和迁移的方案，以及需要保留的迭代设计。
外层文档说明当前有效方案；versions/ 保存迭代当时的方案，按需创建。
已有业务规则见[业务说明](../domain.md)，系统现状和未实施能力见[架构说明](../architecture.md)，CLI 契约继续维护在[命令参考](../cli.md)。

## 新增与维护

- 需要明确业务边界、方案和验收标准时新增文档，简单修改不要求单独成文。
- 文件名按需求或功能主题命名；历史版本文件名包含日期、版本和主题。
- 文档说明目标、范围、用户可见行为、基本架构、验收标准和当前状态；不复制源码、提交版本或具体开发步骤，避免随实现变化重复维护。
- 草案及尚未实施的设计明确标注状态；功能落地或迭代完成后更新外层方案。
- 历史方案注明当时的日期、版本和状态，不随后续迭代改写；在当前方案中关联历史版本。
- 长期架构、领域规则和开发约定的变化同步更新到对应基础文档。
- 重要特殊取舍的历史依据记录在 decisions/，方案中保留引用。
- 两类索引均按下表的列名和顺序维护，新增文档时追加一行，文档使用相对链接；无文档时只保留表头和分隔行。
