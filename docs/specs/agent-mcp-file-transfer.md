# MCP 文件传输设计

状态：下载已接入共享核心与 CLI／GUI MCP；上传为待实现设计，先实现本机直读，再补充 HTTP 中转。下载的 CLI 接入以本机自动化与集成测试为验证范围，macOS 原生及真实 Agent 客户端仍需验收。更新日期：2026-11-03。

本文说明文件传输的核心流程、来源与交付方式、压缩还原及临时文件边界。通用服务、认证及任务规则见 [Agent MCP 接入设计](agent-mcp.md)，已实现能力的操作说明见 [MCP 用户指南](../manual/agent-mcp.md)。

## 目标与范围

用户通过 Agent 在调用方与目标服务器之间传输单个文件、多个文件或目录。服务负责协议选择、内容准备、传输、必要的还原及临时文件清理。下载也支持正在追加的日志。

下载优先直接保存到服务电脑，上传优先由服务读取本机源文件；调用方与服务不共享文件系统，或服务缺少对应的本机读写权限时，通过独立 HTTP 接口交付或接收内容。压缩用于减少服务与目标服务器之间的传输量，与是否经过 HTTP 中转分别决定。

目标服务器需提供 POSIX 环境、Python 3.7 及以上版本和非交互 SSH 命令通道。只处理普通文件与目录，符号链接和特殊文件明确报错。下载要求远端账号可读源文件，上传要求服务或调用方可读源文件、远端账号可写暂存位置和最终目标。中转和协议回退不改变账号权限。

| 能力 | 当前状态与实施顺序 |
| --- | --- |
| 下载：直接保存与链接领取 | 已实现，继续维护现有行为 |
| 上传：本机直读、压缩传输及远端还原 | 待实现，优先完成；CLI 与 GUI 使用相同能力 |
| 上传：HTTP 接收与暂存 | 待实现，在本机上传完成后补充，复用同一远端上传流程 |

公网部署、多用户隔离和跨服务重启恢复任务不在本方案范围内。上传首版不覆盖已有目标，也不合并已有目录；覆盖与合并不通过协议回退或解压命令隐式实现。

## 三方职责与通用规则

| 参与方 | 职责 |
| --- | --- |
| MCP 调用方 | 明确目标、源文件归属及保存位置，发起并等待任务；按结果完成 HTTP 领取或提交内容，告知实际完成情况 |
| MCP 服务 | 选择协议及来源／交付方式，准备与传输内容，执行必要检查，管理任务及临时文件 |
| 远程服务器 | 在已有授权下提供文件读取、写入、压缩还原、最终发布和清理能力 |

本文中的“本机”指运行 MCP 服务的电脑。调用方路径不自动等于服务电脑路径；服务不能仅凭相同路径字符串、请求来源地址或监听配置推断双方共享文件系统。下载当前按运行配置选择默认交付方式；上传的本机来源须明确属于服务电脑可访问的文件系统。

MCP 工具传递目标、路径、任务状态和结果，HTTP 接口传递文件内容，文件正文不进入模型上下文。HTTP 接口沿用同一服务的网络与 TLS 约束，不另行部署文件服务。调用方无法访问接口或无法发送本地文件时，应报告尚未交付，不能只凭工具调用成功报告传输完成。

下载和上传均绑定明确目标及登录身份，使用任务专用连接，不占用正在执行命令或供人操作的终端。引用已有连接只取得固定目标身份，取消传输不关闭其他会话。SFTP 与 ZMODEM 分别检查实际可用能力，并遵守相应授权与访问策略。

例如“把 test207 最新的日志下载到我的下载目录”，调用方应先确定具体源路径；“把本机 config 目录上传到 test207 的 /opt/app”则需确认源目录属于哪台电脑。用户无需选择传输协议，服务分别报告已接收、已准备和最终交付的进度。

### 交付方式与保存位置

交付方式由任务受理时的运行配置决定，不新增手动选择项：

| 运行配置 | 默认交付方式 |
| --- | --- |
| 未允许局域网访问，或监听回环地址（如 `127.0.0.1`、`::1`、`localhost`） | 直接保存 |
| 允许局域网访问且监听非回环地址（含 `0.0.0.0`、`::`） | 下载链接 |

这是交付策略，不用于识别调用方的真实设备；同机访问共享监听也会得到链接。

| 交付方式 | 保存位置与完成含义 |
| --- | --- |
| 直接保存 | 写入服务电脑上已存在的绝对目录，默认使用系统下载目录。服务完成必要解压与检查后返回最终路径，可直接使用 |
| 下载链接 | 服务保留准备包，返回单个文件的下载地址及格式、还原说明。保存目录属于调用方，服务不按自身操作系统解析或写入它 |

直接保存只有在确认写入权限不足时才回退为链接，继续使用同一份准备包；路径无效、磁盘不足或解压失败仍明确失败。两种方式均要求重名另存，不覆盖文件、不合并已有目录。

### 协议自动适配、连接与缓存

优先使用 SFTP，并实际确认暂存位置同时满足 SSH 可写、SFTP 可读。资产配置只是探测线索；SFTP 根限制在 home 或临时目录时，仍可将 SSH 账号可读的其他位置的文件压缩到该暂存位置后下载。

SFTP 不可用或传输失败时，尝试通过专用 SSH 通道执行 `sz`（ZMODEM）。协议回退复用已经准备好的内容，不重新读取源文件；源文件、压缩或容量错误不通过切换协议掩盖。

协议探测结果按目标与登录身份在内存中短期缓存，失效后重新探测，服务重启清空。

### 文件准备、压缩与校验

服务通过 SSH 在远端准备固定内容的传输文件；两种交付方式使用相同的内容和布局：

| 请求内容 | 传输形式 | 还原后的布局 |
| --- | --- | --- |
| 单个普通文件或日志 | `.gz` | 原文件，不加外层目录 |
| 单个目录，包括空目录 | `.tar.gz` | 保留原目录名及内部层级 |
| 多个独立来源 | `.tar.gz` | 共用一层结果目录，保留各自名称与层级 |
| 单个已有压缩文件 | 原样传输 | 保持原文件，不再次解压 |

重复路径及父目录包含的子路径只收录一次，布局按去重后的独立来源确定。不同来源同名时另名保留并说明对应关系；不按文件内容去重。

只解开服务新增的压缩层，内部已有压缩文件保持原样。链接交付直接使用准备包，不在服务端解压重打包。单个文件无法压缩但可以安全准备时可原样传输并告警；目录或多个文件无法打包时失败。

#### 正在写入的日志

每个文件以实际开始读取时的长度确定本次范围，之后追加的内容留给下次下载；重命名轮转继续读取原文件，截断导致内容不足则失败。不承诺多个文件来自同一时刻，也不提供文件系统快照保证。

#### 校验责任

服务检查传输长度及安全交付所需的内容；直接保存时完成必要的还原检查，链接交付时由调用方正常下载并按结果说明解压。任何传输、写盘或解压错误都必须如实报告。

不计算文件内容 SHA-256，也不要求 Agent 追加哈希、独立压缩包测试、远端逐文件对账或 `rsync`。直接保存成功的文件可直接使用；链接模式仅需完成领取及必要的解压。

### MCP 工具、等待与完成语义

两种交付方式共用四个工具：

| 工具 | 作用 |
| --- | --- |
| `download_files` | 发起任务，返回任务 ID 或短任务的最终结果 |
| `get_download` | 长等待查询同一任务，默认等待 20 秒，最长 30 秒 |
| `list_downloads` | 找回服务仍保留的任务 |
| `cancel_download` | 请求取消，并继续查询直到确认结束或结果未知 |

调用方持续长等待至终态，无需每秒轮询。等待窗口结束不取消任务；相同请求键重试返回原任务，结果未知或记录过期不得自动换键重做。

`status=completed` 表示服务端任务完成；`files_ready=true` 表示服务端最终文件可直接使用。链接结果仍需调用方领取，不能仅凭任务完成就报告文件已保存。取消已完成任务不删除最终文件或撤销链接；中断一次 HTTP 领取只影响该次请求。

### 下载链接与生命周期

文件通过独立 HTTP 接口领取，不进入模型上下文。链接使用当前请求可访问的服务地址，沿用服务的网络与 TLS 约束，并携带仅授权单个文件的领取凭据。调用方无法访问时应报告尚未领取，不改走远端命令重新下载。

领取文件保存在应用自管缓存中，与用户最终文件分开。缓存保留可识别的归属和到期信息，领取授权只在当前服务实例内有效。

链接从就绪起有效 **30 分钟**，查询、HEAD 和重复领取均不续期。到期拒绝新领取，已经开始的传输可在自身时限内完成。中断后可在有效期内整包重试，不承诺断点续传，也不重新读取源文件。

任务历史回收、退出 JumpServer 登录或删除 Profile 不影响已就绪链接的原有效期；停止或重启 MCP 会使旧链接失效。

| 文件用途 | 生命周期 |
| --- | --- |
| 远端准备包 | 不再使用且相关进程确认结束后清理，不等待调用方领取。异常残留报告精确位置，不按名称前缀批量删除 |
| 服务端领取缓存 | 就绪后保留至到期，保护活动传输；结合启动清理、每分钟扫描和任务／领取结束时清理回收。重启在确认独占后处理可识别旧残留 |
| 调用方的自动压缩传输包 | 成功解压后清理；失败或用户要求保留时保留，原样下载的压缩文件及既有文件不删除 |
| 最终用户文件 | 不受任务、缓存或服务生命周期影响 |

清理失败单独告警，不否定已经完成的交付；未删除的缓存仍占额度。服务不误删未知文件或其他任务的内容，异常退出后的远端残留不自动清扫。

## 上传

本节为待实现设计。本机直读优先交付，HTTP 中转随后补充；两种来源共用压缩格式、远端传输、还原发布、查询与取消规则。上传最终结果是目标服务器上可直接使用的文件或目录。

### 来源选择与实施顺序

| 来源条件 | 处理方式 |
| --- | --- |
| 调用方明确源路径属于服务电脑，且服务可以读取 | 直接读取源文件，不先经 HTTP 复制一份 |
| 本机来源明确，但服务读取权限不足 | 返回需要调用方提供内容的结果，由有读取权限的调用方通过 HTTP 提交 |
| 源文件位于其他电脑或调用方独立的文件系统 | 使用 HTTP 中转，不在服务电脑尝试读取同名路径 |
| 本机路径无效、文件不存在、源内容变化或准备失败 | 明确失败，不伪装为权限不足，不自动进入 HTTP 中转 |

第一阶段接收明确的本机源路径和远端目标目录，完成本机读取、压缩、协议适配及远端发布。尚未提供 HTTP 能力时，不能将需要中转的请求报告为已接收文件或已开始远端上传。

第二阶段由调用方通过独立 HTTP 接口提交内容。服务无读取权限时不能自行完成这一步；调用方也无法读取源文件，或没有 HTTP 文件发送能力时，上传无法继续。

```mermaid
    U_STAGE --> U_RESTORE
    U_RESTORE --> U_PUBLISH
    U_PUBLISH -->|"发布结果"| U_STATE
    U_SEND -.->|"进度或异常"| U_STATE
    U_STAGE -.->|"失败或状态未知"| U_FAIL
    U_RESTORE -.->|"失败或状态未知"| U_FAIL
    U_FAIL -.-> U_STATE
    U_WAIT --> U_STATE
    U_STATE -->|"未结束"| U_WAIT
    U_STATE -->|"已结束"| U_RESULT
    U_STATE -.->|"停止使用"| U_CLEAN
    U_STATE -.->|"远端进程已确认结束"| U_REMOTE_CLEAN
```

HTTP 接收失败不触发远端上传。提交时过期、额度不足或目标不可用，应返回明确结果；图中的远端发布也可能部分完成，不能据此将所有来源标记为成功。

### 准备与自动压缩

上传沿用下载的传输形式：单个普通文件准备为 `.gz`，目录或多个文件准备为 `.tar.gz`，单个已有压缩文件原样传输。仅解开本次为传输添加的外层，用户原有压缩文件及目录内部的压缩文件保持原样。

本机来源由服务读取和准备，不要求调用方安装打包命令。需要压缩时先生成任务专用准备包，完成后确定实际体积，远端传输重试和协议回退复用同一份包。准备包属于本机上传的内部临时文件，不是等待调用方提交的 HTTP 中转缓存。

原样传输的本机文件可直接通过已打开的源文件读取，不要求先复制整份内容。读取范围以打开时的长度为准，传输期间源内容应保持不变；可检测的身份变化、截断或修改导致失败。不承诺源文件快照，也不依靠重新打开路径处理协议重试。

HTTP 来源由调用方在发送前准备传输包，服务接收后直接用于远端传输，不先完整解压再打包。这样两段网络传输使用同一份内容，大小限制均针对实际传输包。提交内容须明确声明原样文件或本次新增的压缩层，以及原名称和相对布局；不能仅根据扩展名猜测是否需要解压。已经是压缩文件的用户源文件应声明为原样传输。

单个文件无法压缩但可以安全准备时可原样传输并告警；目录或多个文件无法打包时失败。重复路径及父目录包含的子路径只收录一次，按去重后的独立来源确定布局。单个文件或目录保持原名称，多个独立来源分别放入目标目录，不添加下载专用的外层结果目录；不同来源同名时在发布前报错，避免隐式改名或覆盖。

准备、传输和还原检查长度、归档结构及格式自带校验；不额外计算文件内容 SHA-256，不要求 Agent 追加压缩包测试或远端逐文件对账。HTTP 准备包在接收后仍是外部输入，远端还原必须验证条目和路径，不能把调用方声明视为已验证的内容。

### 远端暂存、还原与发布

压缩包接收位置与还原位置分别选择：

| 位置 | 要求 |
| --- | --- |
| 远端接收暂存位置 | 当前传输协议可写，SSH 可读、可清理；SFTP 使用时实际验证路径映射，不固定为 `/tmp` |
| 目标附近的还原位置 | 在已存在且可写的目标目录内创建本任务临时位置，与最终文件位于同一文件系统 |
| 最终位置 | 位于调用方指定的远端目标目录下，按源名称及布局发布 |

服务先检查目标目录和冲突，再传输准备包。SFTP 优先，不可用或可回退的传输失败时，通过专用 SSH 通道执行 `rz` 接收同一份内容；上传写权限和 `rz` 能力单独探测，不能由下载可用推断。切换协议前确认前一次接收已停止，并隔离或清理其半成品；无法确认时报告未知，不继续发送。源文件、容量、目标写权限或还原错误不通过换协议掩盖。

收齐后，在最终目标旁的任务临时位置解压并检查内容；原样文件也先在该位置准备好，再发布。归档只能还原到本任务目录，拒绝绝对条目路径、路径越界、重复冲突、链接和特殊文件，保留空目录。还原和清理都不得跨入其他任务或既有文件。

例如上传本机 `config/` 到远端 `/opt/app`，最终结果为 `/opt/app/config/`。传输包可以先放在账号 home 下已验证的暂存位置，还原时在 `/opt/app` 内创建任务临时目录，得到完整 `config/` 后再发布为最终名称。若目标目录可同时通过 SFTP 和 SSH 访问，也可在目标附近接收准备包。

发布前再次检查目标，确保并发产生的同名内容不会被覆盖。单个文件或新目录在同一文件系统中通过不覆盖已有目标的方式重命名发布；不支持所需发布语义时明确失败。多个独立来源逐项发布，不承诺整批原子成功；部分完成时保留已发布内容，并分别列出成功、失败或未知项，不自动回滚删除最终文件。

远端账号没有目标写权限时直接失败，不自动提权。只有必要还原、检查和最终发布均完成，才能报告对应文件上传成功。

### HTTP 接收与任务控制

上传的业务动作包括发起本机任务、准备 HTTP 接收、提交已接收内容、查询、列出及取消。具体工具名称和参数在实施时确定；两种来源的远端任务使用相同的等待和结果语义。

HTTP 中转按以下顺序运行：

1. 调用方声明准备包大小、内容形式和远端目标意图，服务预留缓存额度，返回接收标识及限时凭据。凭据只允许写入指定接收对象，不允许选择服务电脑上的保存路径。
2. 调用方通过 HTTP 发送文件，服务流式写入半成品并核对实际长度。未收齐的内容不可提交；中断后仅在原接收资格有效且前一次写入已结束时整包重试，不承诺断点续传，不允许并发写入同一对象。
3. 完整接收后，内容固定且不可再次覆盖。调用方通过 MCP 提交远端上传，服务重新校验目标身份、授权、缓存有效期和任务额度；提交成功后保护该内容直到任务不再使用。
4. 调用方持续长等待查询原任务，直到远端完成、失败、取消或未知。HTTP 接收成功只表示内容到达服务电脑，不表示已上传到目标服务器。

本机任务在受理后后台准备和传输；若因源读取权限不足需要调用方提供内容，结束本机任务、清理已产生的准备半成品，并返回后续接收所需信息，不长期挂起任务等待文件。HTTP 接收不提前占用远端连接，完整内容提交后才受理远端任务。任务查询默认等待 20 秒，最长 30 秒，等待结束不取消任务或延长原时限。来源准备、远端接收、还原及发布分别报告进度，最终结果包含实际远端路径和逐项状态。

准备接收和提交远端任务分别去重，重复请求返回原接收对象或原任务，不能重复上传或发布。一个接收对象在被任务接管后不能再次派生另一个远端任务；结果未知或记录过期不得自动换键重新提交。取消需继续等待确认；已发布文件不因取消、缓存过期或任务历史回收而删除。

### 上传临时文件与生命周期

HTTP 接收凭据自签发起有效 **30 分钟**，到期拒绝新的接收请求，已开始的接收仍受独立传输时限约束。完整接收后，待提交内容自就绪起保留 **30 分钟**；查询和重复请求不续期。到期未被任务接管则拒绝提交并自动清理，已经接管的任务继续使用至完成或停止。

| 文件用途 | 生命周期 |
| --- | --- |
| 本机原始源文件 | 属于用户，服务不修改或删除 |
| 本机上传准备包 | 跟随任务，不再使用后清理；无需等待 HTTP 缓存有效期 |
| HTTP 接收半成品 | 中断、取消或接收超时后清理；未释放的额度和残留继续计入缓存上限 |
| HTTP 完整暂存内容 | 未提交时按就绪有效期回收；提交成功后由任务保护，任务结束且不再使用时释放 |
| 远端接收包与还原半成品 | 跟随任务，在相关进程确认结束且不再使用后清理；不等待 HTTP 缓存到期 |
| 已发布的远端文件 | 不受任务、缓存或服务生命周期影响 |

HTTP 缓存与下载领取缓存分开管理，沿用接收前预留、启动清理、每分钟扫描及任务结束时回收的原则；不为新请求提前删除尚有效的待提交内容。历史回收不延长或提前结束未提交内容的有效期，提交仍须重新验证当前远端授权。停止或重启使旧接收凭据及未提交内容失效，不恢复上传任务；在确认缓存独占后回收可识别的本机残留。

远端状态无法确认时保留必要临时内容，并报告精确位置；不按名称前缀批量删除，不在重启后自动扫描远端清理。清理失败单独告警，不否定已确认的最终发布，也不能把残留当作已释放容量。调用方自行生成的传输包在确认完整接收后可清理，用户原始文件不受影响。

## 容量与失败边界

下载的以下限制已实现；上传按相同的传输体积口径设计，尚待实施。单项传输文件最多 **1 GiB**，按压缩包或原样文件的实际体积计算，本机来源和 HTTP 中转、SFTP 和 ZMODEM 均一致。HTTP 上传先由调用方准备传输包，不以“先接收超过上限的原始文件、随后再压缩”绕过限制。

### 下载限制

| 对象 | 当前约束 |
| --- | --- |
| 领取缓存 | 总量 **8 GiB**、最多 **50 个**，包含接收预留和未删除残留；不提前删除有效链接来腾空间 |
| 下载任务 | 最多同时 4 项；默认时限 30 分钟，最长 1 小时 |
| 源路径与条目 | 每项最多 100 个源路径，目录展开最多 1000 项 |
| HTTP 领取 | 全局最多 4 路，同一文件最多 2 路；连续 60 秒无发送进展或单次达到 15 分钟时终止该次领取 |

### 上传限制

| 对象 | 设计约束 |
| --- | --- |
| HTTP 暂存缓存 | 总量 **8 GiB**、最多 **50 个**，与下载缓存分别计量；包含接收预留、活动任务持有的内容和未删除残留 |
| 上传任务 | 最多同时 4 项；受理远端任务后默认时限 30 分钟，最长 1 小时，覆盖本机准备、连接、传输及发布 |
| 源路径与条目 | 每项最多 100 个源路径，目录展开或归档还原最多 1000 项 |
| HTTP 接收 | 全局最多 4 路，同一接收对象只允许 1 路写入；连续 60 秒无接收进展或单次达到 15 分钟时终止该次接收 |

1 GiB 限制不用于压缩前或还原后体积；这些阶段仍受磁盘空间和任务时限约束，本机内部准备包也受单项传输上限约束。HTTP 接收资格和就绪内容的有效期独立于远端任务时限，HTTP 发送或接收时限独立于 MCP 查询窗口。HTTP 文件传输并发已满返回 `429` 和 5 秒重试提示；缓存额度不足或传输超限时明确失败，不通过分卷、切换协议或反复重试绕过。

两个方向均受共享连接与操作记录容量约束，没有名额时不得中止其他任务来腾出空间。取消、超时或部分失败不报告整项成功；远端状态无法确认时报告未知及必要残留，不自动重新发起任务。

## 验收关注点

CLI 与 GUI 须分别核对同一能力的来源／交付选择、任务控制、结果和清理行为；共享规则的验证不能替代两个宿主的实际接入验证。

### 下载验收

验收围绕三条主线：两种交付方式都能完成用户下载；SFTP 回退到真实 `sz` 时内容及目录布局保持一致；失败、取消、到期和重启时完成语义及清理边界正确。

2026-10-23 已在 Windows 服务端与 test207（Python 3.12.3）之间，用 SFTP 根之外的临时样例验证本地保存、链接领取、真实 `sz` 回退、压缩解压、去重与重名另存、权限回退和临时文件清理。跨设备局域网、macOS 原生运行及最低 Python 3.7 环境未实测。

### 上传验收

以下均为待实现能力的验收要求，不代表已经通过验证。

第一阶段验证本机直读：普通文件、空文件、目录、空目录、多来源及已有压缩文件得到预期最终布局；不经过 HTTP 接收，任务结束清理内部准备包，用户源文件保留。源路径归属明确，读取权限不足与路径错误、文件变化和准备失败分别表达。

远端验证 SFTP 根受限时的暂存映射、写权限探测及真实 `rz` 回退，确认两种协议使用同一份准备内容；缺少目标写权限、已有同名内容、发布前发生冲突、解压失败和部分发布均不能误报整项成功。归档越界、链接、重复冲突及特殊文件不会修改临时范围外的内容，无法确认远端状态时报告未知及必要残留。

第二阶段验证 HTTP 中转：跨设备和本机权限不足时由调用方发送内容，完整接收后才允许提交，不能把接收成功当作远端完成。覆盖大小和额度预留、短收与超收、并发写入拒绝、中断重试、提交去重、就绪后禁止覆盖、过期未提交清理及活动任务保护；停止、重启和历史回收不误删最终文件，也不自动重放上传。
