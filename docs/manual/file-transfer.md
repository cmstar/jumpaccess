# SSH 终端内上传和下载文件

本指南介绍如何在 JumpAccess 桌面客户端或 `jumpctl ssh` 中使用 `rz` / `sz` 传输文件，以及如何选择下载保存位置、查看进度和取消传输。

## 开始前

先建立一条可用的 SSH 连接。CLI 的登录和连接步骤见[CLI 入门指南](cli-quick-start.md)。以下命令区分“本机执行”和“远端执行”，示例中的别名、目录和文件名需要替换成自己的值。

SSH 连接的目标服务器需要安装 `lrzsz`，并且 JumpServer 策略允许相应方向的传输。

`rz` 和 `sz` 在远端执行，方向以远端为准：

| 远端命令 | 远端的动作 | 你要完成的操作 |
| --- | --- | --- |
| `rz` | 接收文件 | 从本机上传到远端当前目录 |
| `sz file1 file2` | 发送文件 | 把远端文件下载到本机 |

传输通过当前 SSH 会话使用 ZMODEM 协议，不依赖 SFTP 权限。桌面客户端的 SFTP 是独立入口，有自己的授权和保存规则。

## 桌面客户端上传和下载

### 上传本地文件

1. 打开目标资产的 SSH Tab，等待连接成功。
2. 在远端进入要接收文件的目录，例如：

   ```sh
   cd /tmp
   ```

3. 确认终端处于 Shell 命令提示符，点击工具栏的上传按钮；也可以在远端直接执行：

   ```sh
   rz
   ```

4. 在系统文件对话框中选择要上传的本地文件，等待完成。

### 下载远端文件

在 Shell 命令提示符下点击工具栏的下载按钮，输入**单个远端文件路径**，例如 `/tmp/report.txt`。按钮接受的是字面路径，不展开 `~`、通配符或 Shell 表达式，也不提供目录浏览。

也可以在远端直接执行 `sz`。例如，先进入文件所在目录，再下载两个文件：

```sh
cd /tmp
sz report.txt app.log
```

默认会弹出本机目录选择框，从系统“下载”目录开始选择。同一批次的多个文件使用同一个保存目录；遇到同名文件时自动添加数字后缀另存，不覆盖已有文件。

### 设置下载保存位置

在“设置 → 终端行为 → 下载保存位置”选择保存方式：

| 分组 | 选项 | 保存行为 |
| --- | --- | --- |
| 每次询问 | 从下载目录开始（默认） | 每次弹出目录选择框，从系统下载目录开始 |
| 每次询问 | 从上次目录开始 | 每次弹出目录选择框，记住上次选择的目录，重启后仍保留 |
| 自动保存 | 保存到下载目录 | 直接保存到系统下载目录 |
| 自动保存 | 保存到指定目录 | 直接保存到填写的本机目录，可手工输入完整路径或点击“选择文件夹” |

“从上次目录开始”首次使用或记住的目录不可用时，回退到系统下载目录。自动保存的目录未设置或不可用时，会改为弹窗选择。

设置保存后作用于下一次传输，工具栏下载和手工执行 `sz` 共用这一规则。CLI 的下载目录单独设置，见下一节。

### 查看进度和取消

顶部工具栏下方显示当前文件的进度和取消按钮，终端也会显示进度。传输期间普通终端输入暂停，切换 Tab 不影响传输，返回时仍可查看状态。

需要停止时，点击传输区域的取消按钮。保存、等待远端确认和结束清理期间，取消按钮会暂时禁用。取消、错误、断连或退出会清理未完成的本地下载文件。

整批上传或下载成功后，顶部中央会显示一次完成提示，例如 `web 下载完成：report.txt`。提示名称优先使用传输所属 Tab 的别名，没有别名时使用资产名称；多文件列出各文件名，下载使用实际保存的名称，不包含本机路径。即使已切换到其他 Tab，也能辨认来源。取消、失败、断连、空批次或上传全部被远端跳过时，不显示成功提示。

## CLI 上传和下载

### 连接并设置下载目录

在本机执行，`web` 是已配置的目标别名，也可以换成可解析的资产目标：

```sh
jumpctl ssh web
```

交互终端会自动识别远端的 `rz` / `sz`。下载默认保存到本机系统“下载”目录：Windows 遵循 Known Folder 的目录重定向，macOS 正式构建读取系统 Downloads 目录。

需要为本次连接指定保存位置时，在建立连接时添加 `--download-dir`。Windows 示例：

```powershell
jumpctl ssh web --download-dir "D:\Downloads"
```

macOS 示例：

```sh
jumpctl ssh web --download-dir "$HOME/Downloads"
```

`--download-dir` 只覆盖本次连接的本地下载目录，不修改持久配置，也不改变远端目录。指定目录应已存在且可写；默认或指定目录不可用时，CLI 会提示 `Local download directory (empty to cancel):`，输入其他本地目录，或留空取消本次传输。

### 上传本地文件

在已连接的远端 Shell 中进入目标目录并执行：

```sh
cd /tmp
rz
```

本机随后显示：

```text
Local file to upload (empty to cancel):
```

输入**单个本地普通文件**的路径并回车，例如 `"D:\Work Files\report.txt"` 或 `~/Documents/report.txt`。路径可以带引号，支持 `~`。这段输入由本机处理，不会发到远端 Shell。空路径或 Ctrl+C 取消选择。

### 下载远端文件

在远端执行：

```sh
sz /tmp/report.txt /tmp/app.log
```

文件会依次保存到本次连接的下载目录，终端先显示 `Download directory: <本地目录>`，再逐个显示下载文件名。遇到同名文件时自动添加数字后缀另存。

### 取消和使用限制

传输期间按 Ctrl+C 取消。取消或失败后，按 Enter 刷新远端提示符；如果远端写入已被流控阻塞，取消或超时会关闭该 SSH 会话，避免进程持续阻塞。

CLI 使用标准 32 位 ZMODEM 文件偏移，单文件必须小于 4 GiB。不支持直接传输目录，需要先打包成文件。

本地传输交互要求标准输入和标准输出都是终端；其中任一个被重定向时，CLI 保持字节透传，不启动本地文件选择、保存或进度显示。通过 `jumpctl proxy` 使用 OpenSSH 或其他兼容客户端连接时，也由外部客户端处理 ZMODEM，`jumpctl proxy` 不使用上述本地文件选择和下载目录逻辑。

## 理解进度和完成结果

两端的本地终端提示都使用英文，服务器原始输出按原样显示。GUI 上传显示 `Upload <本地源文件完整路径>`，下载显示 `Download to <实际保存文件完整路径>`；CLI 显示 `Upload <文件名>` 或 `Download <文件名>`，下载目录另行显示。同名另存时显示实际保存的文件名。进度行原地刷新，显示已传输大小和百分比。

收到全部数据后仍可能显示 99% 和 `Saving`；上传等待远端确认时显示 `Waiting for confirmation`。只有保存成功或收到远端完成确认后，才显示 100% 和 `Complete`，零字节文件也一样。

每个成功完成的文件都有耗时和平均速度，GUI 与 CLI 的分隔符略有不同：

```text
GUI: Complete · Elapsed 2.00 s · Avg 512.00 KiB/s
CLI: Complete - Elapsed 2.00 s - Avg 512.00 KiB/s
```

`Elapsed` 从该文件开始传输计到本地保存或远端确认完成，包含本地读写和确认时间，不包含选择文件／目录及文件间等待。`Avg` 按本次新增传输的文件字节数除以耗时计算；CLI 上传续传时排除远端已有内容，也不重复累计重传字节。多文件分别统计，取消、失败或被远端跳过的文件没有成功统计。

## 常见问题

### 桌面客户端的上传或下载按钮是灰色

两个按钮始终显示，并按方向检测能力：远端有 `rz` 时可上传，有 `sz` 时可下载。检测中、未找到命令、探测失败、断连或正在传输时，相应按钮不可用，悬停提示会标明“当前不可用”。

连接后会通过独立 SSH 命令通道检查 `command -v rz` 和 `command -v sz`，最多等待 5 秒。部分 JumpServer 网关会拒绝该通道，此时显示“无法检测”，不会把探测命令插入当前 Shell，也不能据此断定远端没有安装命令。

可以在远端 Shell 手工执行 `rz` 或 `sz 文件名`；识别到协议握手后，客户端会按对应的文件选择或下载保存规则开始传输，并启用该方向的按钮。命令存在不代表堡垒机允许传输，被策略阻止或超时仍会显示错误。

### 下载时出现空文件，或接收完成后仍在保存

选择目录后，客户端会先创建空文件以保留文件名，再写入内容。下载使用最多 50 MiB（50 × 1024 × 1024 字节）的共享内容缓冲；额度充足时，小文件收齐后保存，大文件分批写入。多个会话共享额度，额度不足时缩小缓冲或直接写入，因此不能用传输过程中的磁盘文件大小判断是否完成。

等待终端显示 `Complete` 后再使用文件。取消、错误或断连会清理未完成的本地下载。这一缓冲额度不代表整个程序的内存上限；实现细节见[架构说明](../architecture.md#桌面-zmodem)。

### 需要传输整个目录

先在文件所在的一端把目录打包，再传输生成的文件。GUI 下载按钮只接受单个文件路径，CLI 同样不提供目录传输。
